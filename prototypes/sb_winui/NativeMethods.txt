// CsWin32 generation list for the S-B swapchain host.
//
// WHY A GENERATOR RATHER THAN HAND-WRITTEN COM DECLARATIONS. IDXGIFactory2
// inherits about twenty methods across IDXGIObject, IDXGIFactory and
// IDXGIFactory1, and a hand-written [ComImport] interface must repeat every one
// of them in exact vtable order. Getting a slot wrong compiles cleanly and then
// calls the wrong function at runtime, which is the worst available failure
// mode: it looks like a Direct3D bug. The generator reads the same Win32
// metadata the OS headers are generated from.
//
// CsWin32 is build-time only; nothing ships with the app.

// O1's hash: the back buffer is copied into a STAGING texture and mapped for
// read, because a render-target texture cannot be read by the CPU. `Map` is
// what makes `RowPitch` visible, and `RowPitch` is why the hash walks rows
// instead of hashing the mapped extent -- the padding past `w * 4` is
// uninitialised memory and would make an exact comparison wobble for a reason
// that has nothing to do with what was drawn.
D3D11_MAP
D3D11_MAPPED_SUBRESOURCE
D3D11_CPU_ACCESS_FLAG

// THE DPI RECEIPT. The manifest (app.manifest, ApplicationManifest in the
// csproj) declares PerMonitorV2, and the harness must be able to ASSERT that it
// took effect rather than infer it from a client-to-surface ratio. So the
// startup row reads the awareness the OS actually gave this window, and the DPI
// the OS actually reports for it: an unaware process is bitmap-virtualised and
// answers 96 for a window on a 150% panel, which is exactly the state that made
// every injected gesture land at 2/3 of its asked point.
GetWindowDpiAwarenessContext
GetAwarenessFromDpiAwarenessContext
GetDpiForWindow
DPI_AWARENESS
